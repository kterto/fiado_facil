# 002.2.1 — Splash and login (S0, A1) [mvp] [delivery]

## Brief
Build the splash (design `docs/design/01-splash.html`) and login screen (design `docs/design/02-entrar.html`) with Firebase email/password auth. Read `.orchestrator/PROJECT-CONTEXT.md` (Invariants, Conventions, Commands) and `docs/foundation/INTENT.md` / `ACTORS.md` before starting.

- **Remove** the "ou" divider and the "Continuar com o Google" button from the design — Google sign-in is out of scope.
- Copy, states and validation exactly as the design: field errors, "E-mail ou senha incorretos. Confira e tente de novo.", too-many-attempts state with disabled reason, offline state "Sem internet. Conecte o celular para entrar.", loading "Entrando...", footer "Sem acesso? Peça ao responsável pelo mercadinho para criar a sua conta.", "Esqueci minha senha" link (target screen comes in the next story — navigate to a stub).
- Splash: valid session → home (works offline); no session → Entrar. After sign-in and on every start, read `usuarios/{uid}` (cache is fine offline): missing or `ativo == false` → sign out and show Entrar with the message "Seu acesso foi desativado. Fale com o responsável pelo mercadinho." (copy not in the design — flag it for review).
- Keep the signed-in `Usuario` (nome, papel) available app-wide via Provider for later stories.
- Home is a placeholder until the client list story lands.

## Acceptance
- Widget tests cover every design state of A1 (empty, field errors, loading, wrong credentials, too many attempts, offline) and the absence of the Google button.
- Integration test on the emulator: seeded active user logs in and reaches home; inactive user is signed out with the message; app restart with a session skips the login.
- format/analyze/test green.
