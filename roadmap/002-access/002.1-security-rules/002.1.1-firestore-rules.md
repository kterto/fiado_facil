# 002.1.1 — Firestore security rules with tests [mvp] [hardened]

## Brief
Replace the deny-all `firestore.rules` with the real rules and an automated rules test suite against the Firestore emulator. Read `.orchestrator/PROJECT-CONTEXT.md` (Invariants, Conventions, Commands) and `docs/foundation/INTENT.md` / `ACTORS.md` before starting.

Rules (deny by default):
- `isActive()`: signed in **and** `usuarios/{request.auth.uid}` exists with `ativo == true`. Accounts without such a doc (self-sign-up is technically possible on the client SDK) can read and write nothing.
- `isDono()`: active and `papel == 'dono'`.
- `usuarios`: read by active users; create/update only by the dono; nobody deletes; a user cannot change their own `papel` or `ativo`.
- `clientes`: read, create and update by active users with field validation (types, nome 1–80, telefone 10–11 digits, endereco ≤ 120, limite int > 0 or null, no `<`/`>` in text, `ativo` bool); no delete.
- `lancamentos` and `pagamentos`: read by active users; create only with `registrado_por == request.auth.uid`, `cancelado == false`, `valor_centavos` int in 1..9999999, `data_hora == request.time` (client writes `FieldValue.serverTimestamp()`), descricao ≤ 100 without `<`/`>`; the **only** allowed update is `cancelado: false → true` with `cancelado_por == request.auth.uid` and no other field changed; no delete.
- CSV export needs no rule (it reads what an active dono can read).

Testing: choose a minimal harness that runs against the emulator (recommended: `@firebase/rules-unit-testing` in a small Node package such as `firestore-tests/`), add the exact command to the `## Commands` and `## Test tooling` sections of `.orchestrator/PROJECT-CONTEXT.md`, and record the choice in the output summary.

## Acceptance
- Rules tests prove, for each collection: unauthenticated denied; signed-in without `usuarios` doc denied; inactive user denied; active atendente allowed for normal operations; dono-only operations denied to atendente.
- Tests prove: `registrado_por` spoofing denied; editing any ledger field denied; un-cancelling denied; delete denied everywhere; `<`/`>` rejected; out-of-range values rejected; `data_hora` not equal to request time rejected.
- The rules-test command is documented in PROJECT-CONTEXT `## Commands` and passes via `firebase emulators:exec`.
