# 001.2.2 — Ledger rules: saldo, limit, overdue, statement, search [mvp] [hardened]

## Brief
Implement the ledger business rules as pure functions in the domain layer. Read `.orchestrator/PROJECT-CONTEXT.md` (Invariants, Conventions, Commands) and `docs/foundation/INTENT.md` / `ACTORS.md` before starting.

- **Saldo** = Σ non-cancelled compras − Σ non-cancelled pagamentos (centavos), over all of a customer's records. Status: > 0 "Deve R$ X", < 0 "Crédito de R$ X", = 0 "Sem débito".
- **Limit**: a new compra is over the limit when the customer has a limit and saldo-after-purchase > limite → flag `acimaDoLimite = true`. Provide the alert text: "{nome} tem limite de R$ X. Com esta compra, vai dever R$ Y. Registrar mesmo assim?". Limit marker on the ficha: "Limite: R$ X" and "(passou)" when saldo > limite.
- **Payment**: "Pagou tudo" amount = saldo when saldo > 0. Overpayment (valor > saldo) yields the crédito text: "{nome} deve R$ X. Com este pagamento de R$ Y, {nome} fica com crédito de R$ Z. Registrar mesmo assim?" (gender-neutral on purpose: the design says "ela"; flag the copy change for review).
- **Overdue** (em atraso): saldo > 0 and no non-cancelled pagamento in the last 30 days. When the customer has never paid, count from the earliest non-cancelled compra that is part of the open balance (so a customer whose first fiado was yesterday is not overdue). State this interpretation in code docs and in the output summary for product-owner confirmation.
- **Statement text** (extrato): header `Mercadinho da Família — Extrato de {nome} — {dd/mm/aaaa}`; the non-cancelled compras and pagamentos since the last point where the running balance was ≤ 0 (chronological, `dd/mm` + type + value + description); closing line with the saldo. When saldo = 0 the body is "Você não tem débitos no Mercadinho da Família."; when saldo < 0 say the customer has credit of R$ X.
- **Search**: normalize names (lowercase, accents removed) for `nome_busca`; filter = normalized query contained in nome_busca; results sorted alphabetically.
- Use an injectable clock; dates in America/Recife (UTC−03:00).

## Acceptance
- Table-driven unit tests for saldo with cancelled items, credit, zero.
- Limit tests: no limit, exactly at limit (not over), 1 centavo over.
- Overdue tests: paid 29/30/31 days ago, never paid with recent and old compras, saldo ≤ 0 never overdue.
- Statement tests: period starts after the last zero/credit point; cancelled entries excluded; zero and credit variants.
- Search tests: "jose" matches "José", "MAR" matches "Maria Souza", alphabetical order.
- Domain coverage ≥ 90% and mutation testing on these rules shows no surviving mutants in saldo/limit/overdue; format/analyze/test green.
