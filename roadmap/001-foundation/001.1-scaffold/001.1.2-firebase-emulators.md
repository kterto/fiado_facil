# 001.1.2 — Firebase wiring and local emulators [mvp] [delivery]

## Brief
Wire Firebase into the app using only the local Firebase Emulator Suite; no real Firebase project exists yet (it is created in a later release story). Read `.orchestrator/PROJECT-CONTEXT.md` (Invariants, Conventions, Commands) and `docs/foundation/INTENT.md` / `ACTORS.md` before starting.

- Add `firebase_core`, `firebase_auth`, `cloud_firestore`.
- Add `firebase.json` with emulators for **auth** and **firestore** (plus the emulator UI) and `.firebaserc` pointing at the demo project id `demo-fiado-facil` (the `demo-` prefix keeps everything offline-only).
- Initialize Firebase with explicit `FirebaseOptions` for the demo project, selected by `--dart-define=FIREBASE_ENV=emulator` (default). Leave a clearly marked place for production options generated later by `flutterfire configure`.
- In emulator mode connect Auth and Firestore to the emulators (Android emulator host `10.0.2.2`, configurable host via `--dart-define`).
- Enable Firestore offline persistence (persistent cache) — the app must keep working without internet.
- Add `firestore.rules` that deny everything (real rules come in a later story) and an empty `firestore.indexes.json`.
- Document in `README.md` how to start the emulators and run the app against them, including prerequisites (Firebase CLI, Java).
- Add an `integration_test/` smoke test that boots the app against the emulators.

## Acceptance
- `firebase emulators:start --only auth,firestore` starts with the repo's config.
- The app boots against the emulators with persistence enabled; no network call reaches a real Firebase project.
- `firebase emulators:exec --only auth,firestore "flutter test integration_test"` runs the smoke test green on an Android emulator.
- `firestore.rules` denies all reads and writes.
- README documents the dev loop; format, analyze and unit tests stay green.
