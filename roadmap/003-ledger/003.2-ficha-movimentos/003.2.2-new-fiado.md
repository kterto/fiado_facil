# 003.2.2 — Register a fiado (T2) with limit alert [mvp] [delivery]

## Brief
Build "Fiado" (`docs/design/08-novo-fiado.html`). Read `.orchestrator/PROJECT-CONTEXT.md` (Invariants, Conventions, Commands) and `docs/foundation/INTENT.md` / `ACTORS.md` before starting.

- Client card with name and saldo; "Valor da compra (R$)" filled by the on-screen keypad (1–9, 00, 0, backspace; right-to-left entry; long-press backspace clears; max R$ 99.999,99); "Descrição (opcional)" with 0/100 counter.
- Validation messages from the domain. "Salvar fiado" writes a `lancamentos` doc with `registrado_por` = current uid, `data_hora` server timestamp, `cancelado: false`, `acima_do_limite` from the domain rule.
- Over-limit modal "Passa do limite" with "Registrar mesmo assim" / "Voltar" — it never blocks the sale.
- Snackbars "Compra de R$ X registrada para {nome}." / "Compra registrada. Será enviada quando houver internet."; return to the ficha. Double taps never create two entries. Unsaved-exit modal per design.
- Target: from the client list, a fiado takes ≤ 4 navigation taps (client → Fiado → Salvar fiado [→ Registrar mesmo assim]) and ≤ 20 s; save confirms in ≤ 1 s.

## Acceptance
- Widget tests: keypad behaviour, max value, description counter, `<`/`>` error, over-limit modal both choices, double tap, unsaved-exit modal.
- Integration test: fiado saved offline appears in the ficha with "Ainda não enviado" and syncs; over-limit entry stored with `acima_do_limite: true`.
- format/analyze/test green.
