# 003.1.1 — Client list and search (T1) [mvp] [delivery]

## Brief
Build the client list (`docs/design/05-lista-clientes.html`) as the app's home, replacing the placeholder and keeping the top bar from the logout story. Read `.orchestrator/PROJECT-CONTEXT.md` (Invariants, Conventions, Commands) and `docs/foundation/INTENT.md` / `ACTORS.md` before starting.

- Repositories in the data layer stream active `clientes`, `lancamentos` and `pagamentos` from Firestore (offline cache included); each row shows name and saldo label from the domain rules ("Deve R$ X" / "Crédito de R$ X" in green / "Sem débito").
- Search field "Buscar cliente" (placeholder "Digite o nome", clear button "Limpar busca") using the domain search; counters "N clientes no fiado" / "N encontrados para “q”" / "Nenhum encontrado"; empty and no-result states with the design copy.
- Offline banner "Sem internet. Pode continuar usando: os dados serão enviados depois." and syncing state "Enviando dados..." (derive from snapshot metadata and/or a connectivity check); loading "Carregando clientes..." and the failed-first-load state with "Tentar de novo".
- Pull to refresh; Android Back clears the search first, otherwise closes the app.
- Fixed "Novo cliente" button (pre-fills the search text as name) and row tap navigate to stubs for the next stories.

## Acceptance
- Widget tests for every design state (list, search hit, no result, empty, offline, syncing, loading, load failure).
- Saldo per client matches the domain rule for seeded data with cancelled entries.
- Search ignores accents and case and filters from the first character.
- Integration test: list renders from cache with the network disabled.
- format/analyze/test green.
