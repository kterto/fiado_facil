# 005.2.1 — Production Firebase, signed APK and owner bootstrap [mvp] [delivery]

## Brief
Prepare the first production release. This story needs the product owner for the steps that require their Google account. Read `.orchestrator/PROJECT-CONTEXT.md` (Invariants, Conventions, Commands) and `docs/foundation/INTENT.md` / `ACTORS.md` before starting.

- Write a runbook (`docs/release/RUNBOOK.md`) for the human steps: create the Firebase project on the **Spark** plan, Firestore in **southamerica-east1** (cannot be changed later), enable Email/Password auth, run `flutterfire configure` for Android, deploy `firestore.rules` and indexes, create the owner's Auth account and its `usuarios/{uid}` doc (`papel: 'dono'`, `ativo: true`) in the console, create the signing keystore (kept out of git).
- Wire production options behind `--dart-define=FIREBASE_ENV=prod`; emulator remains the default for development.
- Configure Android release signing from a non-committed `key.properties`; `minSdkVersion 26`; app name and icon from the design.
- `flutter build apk --release --dart-define=FIREBASE_ENV=prod` produces an installable APK; document sideload installation and the pilot checklist (baseline loss measurement from the notebooks, ~2-week parallel run, acceptance term).

Commit with trailer: Roadmap-Story: 005.2.1

## Acceptance
- Runbook complete and reviewed by the product owner.
- Release APK installs on an Android 8+ device and logs in against production after the owner completes the runbook.
- No secrets or keystore committed; `.gitignore` covers them.
- Human validation: owner confirms login and one fiado on a real phone.
