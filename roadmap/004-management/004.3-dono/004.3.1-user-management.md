# 004.3.1 — User management (owner only) [mvp] [delivery]

## Brief
Give the owner (papel `dono`) a "Usuários" screen to create and deactivate users. Only visible to the dono. Read `.orchestrator/PROJECT-CONTEXT.md` (Invariants, Conventions, Commands) and `docs/foundation/INTENT.md` / `ACTORS.md` before starting. There is no design file for this screen. Build it only from the existing design system (tokens, type scale, components and patterns in `docs/design/*.html` and the app theme), and add a visible note in the story's output summary that the screen **needs design validation** by the product owner.

- List users (nome, e-mail, papel, ativo).
- Create: nome, e-mail, senha inicial (≥ 6 chars). Create the Firebase Auth account **without signing the owner out**, using a secondary `FirebaseApp` instance, then sign that secondary instance out and write `usuarios/{newUid}` with `papel: 'atendente'`, `ativo: true`, `criado_em`. No Cloud Functions (Spark plan).
- Deactivate / reactivate a user by toggling `ativo` (Auth account is kept; rules deny inactive users).
- Needs internet; show the offline message pattern when offline.

## Acceptance
- Integration test on the emulator: owner creates a user who can then log in; deactivated user is rejected at login; an atendente cannot open the screen and rules deny their writes to `usuarios`.
- Owner stays signed in after creating a user.
- Output summary flags the screen for design validation.
- format/analyze/test green.
